Cấp phát Khóa Động & Xử lý In-Memory

sequenceDiagram
    participant App as Flutter App

    App->>Nat: Khởi tạo SDK (API Key)
    Nat->>Cpp: Gọi C++ khởi tạo Engine
    Cpp->>Auth: Request Session Key
    Auth-->>Cpp: Trả về Dynamic Key (AES-256)
    
    App->>Nat: Yêu cầu tải Map Tile
    Nat->>Cpp: Đẩy request xuống C++
    Cpp->>Tile: Fetch Encrypted Tile
    Tile-->>Cpp: Trả về Tile (AES-GCM)
    
    Cpp->>Cpp: Giải mã và đẩy thẳng vào GPU

Ưu điểm: Giấu nhẹm Endpoint

Hacker đọc code Dart sẽ không hề biết địa chỉ URL API của bạn là gì, truyền tham số ra sao. Mọi thứ cấu hình mạng đều nằm sâu trong file mã máy .so.

Nhược điểm: Tốn nguồn lực Dev

Xử lý HTTP Request, SSL/TLS Certificates, Retry logic, Timeout bằng C++ phức tạp và mất thời gian hơn rất nhiều so với viết bằng Dart/Java.

Ưu điểm: Code cực nhanh & Thực dụng

Tận dụng được tối đa sức mạnh quản lý Network của hệ sinh thái Flutter (Gói Dio, Cache, Retry). Lõi C++ giờ đây cực kỳ mỏng nhẹ, chỉ đóng vai trò như một "Chiếc máy giải mã cầm tay" vô cùng an toàn.

Nhược điểm: Lộ URL API

Hacker dịch ngược app sẽ thấy URL Backend của bạn. Tuy nhiên, nếu Backend yêu cầu Token xác thực chặt chẽ và luồng Payload vẫn bị mã hóa AES, thì rủi ro này là hoàn toàn có thể chấp nhận được ở mức thương mại.
